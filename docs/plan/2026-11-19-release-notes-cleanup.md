# Release 说明、资产和发布状态优化

## 目标

后续版本的说明只展示普通提交信息和必要的签名状态提示；不上传额外源码压缩包；将发布状态由 Pre-release 改为正式 Release。已有 `v0.1.0` 不作修改。

## 发布说明

1. 关闭 GitHub 自动生成的 Release notes，保留现有认证或未认证状态提示，新增提交列表；不显示作者、分支、PR、贡献者或合并提交。每个普通提交展示提交标题，即 commit message 的第一行；不做摘要、翻译或生成额外内容。
2. 当前 Tag 仍须严格匹配 `vX.Y.Z`。选择当前 Tag 所指提交的祖先中最近的、严格匹配 `vX.Y.Z` 的其他 Tag，作为上一个 Tag。分支上不可到达的 Tag 不参与选择；如没有上一个 Tag，列出当前 Tag 可到达的所有普通提交。
3. 范围内按 Git 提交历史获取提交标题，排除所有合并提交。使用明确的 Git 提交范围，不调用 GitHub 自动生成说明接口；处理中文及特殊字符，避免通过 shell 拼接执行提交文本。多个标签指向同一祖先时使用确定性规则，并为无提交结果显示明确提示。
4. 发布任务必须检出完整历史和所有所需 Tag，验证当前 Tag 对应预期提交；缺少历史、Tag 或 Git 命令失败时停止发布，不能静默生成不完整记录。不得在日志泄露任何 Secrets。

## 资产和状态

1. 发布汇总不再生成或上传 `TapSayAudio-2ch-<版本>-source.tar.gz`。公开资产严格为两个架构 DMG 与 `SHA256SUMS.txt`；校验文件仅包含这两个 DMG 的实际文件名和散列。
2. 更新汇总、公开资产审计、发布前本地及远端资产集合检查和相关测试。保留所有架构、散列、第三方分发审查和签名、公证检查。单独源码归档工具可保留，但不属于公开 Release 流程。
3. 使用 GitHub 自动提供的 Source code ZIP 和 tar.gz。它们是 Tag 的仓库快照，不包含额外源码归档脚本运行时生成的 `BUILD-PROVENANCE.json` 和 `SOURCE-REVISION.txt`；上线前核对构建所需源码、许可证和上游源码已被 Git 跟踪且在 Tag 快照中。
4. 发布时取消 `--prerelease`，发布后校验 `isPrerelease` 为 `false`。保留草稿上传、远端资产验证、失败处理和禁止覆盖已有 Release 的规则。未认证 DMG 仍带 `Unverified`，该标识与 Release 发布状态无关。

## 实施与验收

1. 修改发布工作流以获取完整历史，再调整提交范围计算与发布说明；测试首个 Tag、连续 Tag、未合并分支 Tag、合并提交、同一提交多个 Tag、特殊字符及缺少历史或标签的失败路径。
2. 调整发布汇总及审计和上传资产集；测试两个 DMG 的散列、缺失或多余资产、认证和未认证模式以及远端资产校验。验证 GitHub 源码快照涵盖必要的仓库跟踪文件。
3. 调整正式 Release 状态及验证；测试草稿转正式状态、错误状态、同名 Release 已存在和失败清理。更新当前使用说明，保留历史记录。
4. 运行相关发布工具测试和 `git diff --check`；不创建真实 Tag、不触发 GitHub Actions，也不修改现有 Release。用户后续自行通过新 Tag 验证。

本规划获用户明确批准后实施；每完成主要文件修改后遵循用户适用的实施确认要求。需要变更规划时先更新并取得批准。
