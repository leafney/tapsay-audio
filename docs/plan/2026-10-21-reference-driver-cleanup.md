# TapSay Audio 从无线麦参考方案重新实现 PRD

日期：2026-10-21
状态：主体已批准；HAL 回调验证发现新增越界，执行暂停。第 14 节为待批准补充，不改变已批准的三项修复范围。
所属仓库：`tapsay-audio`。
实施分支：`feat/61021`。

## 1. 问题与目标

TapSay Audio 首版围绕遥控器 16 kHz 源格式提前收缩驱动能力、改变默认运行率和对象布局。用户实际安装后反复遇到声卡就绪或切回失败，后续多轮修改仍未完成稳定验收。参考无线麦的 MiRemoteV 2ch 在用户环境中长期可用；在 TapSay 驱动实际运行率对齐到 48 kHz 后，曾得到短时真实切回成功样本。现有 TapSay 仓库同时维护旧正式配置和两套实验配置，以及历史构包入口与多份过期记录，已不适合作为新产品基线。

本 PRD 的目标是**停止沿用当前 TapSay 驱动与安装工具的实现**，从固定的无线麦虚拟声卡方案出发建立新的、独立的 TapSay Audio。先复现参考，再做产品身份和独立分发所必需的改动，最后验证。任何采样率表收缩、隐藏设备删除、缓冲区调整、额外恢复策略或提高“理论效率”的音频优化均排在基线验收之后。

“从零”指新源码、构建、安装和卸载实现从冻结参考与产品合同重新建立，不从现有 TapSay C 文件、Swift 事务代码或实验 profile 派生。保留现有 Git 历史，旧代码只用作身份、升级兼容、失败案例和验收合同的核对材料。完成新实现并通过验证后，再从当前工作树移除旧代码、构建脚本和过期文档。

## 2. 用户故事

1. 作为遥控器用户，我希望首次选择 TapSay Audio 和从 MiRemoteV 切回后都能一次长按完成语音输入。
2. 作为用户，我希望设备在系统中名为 `TapSay Audio 2ch`，且与 MiRemoteV、BlackHole 并存。
3. 作为用户，我希望安装包双击即可安装，并提供单独的卸载入口。
4. 作为已安装旧版的用户，我希望新版本覆盖安装后能实际加载、运行，而不被旧 16 kHz 系统记录拖回失败状态。
5. 作为用户，我希望安装失败可以恢复原有 TapSay 驱动，卸载后系统输入与输出列表不再保留 TapSay 设备。
6. 作为开发者，我希望能用固定源码提交、补丁和参数重现参考驱动，再清楚看到 TapSay 必需差异。
7. 作为维护者，我希望唯一构建入口就是准备发布的 48 kHz 参考方案，不会无意生成旧 16 kHz 版本。
8. 作为其他软件用户，我希望保留参考驱动的格式能力，并在 README 中看到已验证软件和采样率的实际范围。
9. 作为发行维护者，我希望首个交付只有 Apple Silicon 安装包、卸载入口、许可材料和对应源码，避免为尚未支持的 Intel 生成安装资产。
10. 作为后续接手者，我希望当前仓库只保留现行规格、源码和验证结果，历史弯路可从 Git 历史追查。

| 音频能力 | 参考的双声道 Float32 输入输出、按顺序支持 8000、16000、24000、44100、48000、88200、96000、176400、192000、352800、384000、705600、768000 Hz；保留隐藏第二设备、缓冲、时钟、IO 与属性语义；初始默认 48000 Hz |
| 架构与系统 | 仅 Apple Silicon `arm64`；macOS 14 起。首轮不构建、不打包、不声明支持 Intel `x86_64` |
| 应用音频源 | 遥控器解码后的 16000 Hz 单声道 Float32 保持源格式；参考无线麦将此源连接混音节点并绑定输出设备，没有在该路径强制写输出节点为 48000 Hz |

参考源码与用户本机已装 MiRemoteV 二进制的逐字节对应关系目前未知。先记录已装设备属性、架构、版本、签名和散列；在隔离目录复建固定参考驱动并比较功能属性。不得覆盖用户的 MiRemoteV 驱动来取得“对照”。无法证明二进制同源时，报告只能称“基于冻结参考源码复现”，不能称与已装包逐字节一致。

TapSay 主程序继续允许用户选择已有的 MiRemoteV 2ch 或 BlackHole 2ch，不强制安装 TapSay Audio。主程序只负责声卡检测、选择、就绪验证和通过 `TapSayAudioDownloadURL` 引导下载；这个配置只有在正式安装包可公开下载并校验后才填入真实地址。

## 4. 实现决策

### 4.1 先复现参考，再做 TapSay 适配

1. 隔离工作区从已校验的 BlackHole 固定源码和无线麦补丁生成原样参考驱动。原样候选只用于构建、静态属性和独立测试，不安装为 MiRemoteV，也不覆盖现有驱动。
2. 保存参考 `arm64` Xcode 构建命令与完整有效设置，记录源码、补丁、产物散列。参考成功前不得开始 TapSay 特有优化。
3. 在新工程中以最小补丁替换产品名称、Bundle ID、设备及 Box/Model UID、独立隐藏设备 UID、插件工厂、版本与许可说明。所有源码差异逐项标注为身份、独立打包必需或已知正确性修复。其他音频运行代码保持参考逻辑。
4. 原参考中已知的数组索引和参数校验问题，先在原样参考测试中记录；首个可安装 TapSay 候选只允许加入前述已批准的三项正确性修复，并分别证明对正常 IO/格式路径无改动。不得为了“完全照抄”把可确认的越界或错误返回写入系统音频服务。
5. 用参考构建与 TapSay 构建做有效宏、设备对象、格式列表、IO 回调、缓冲、时钟和完整设置对照。允许差异只包括本节列出的项；每项有来源和测试结果。任何新增差异先写入 PRD 并获批准。

### 4.2 新建独立安装、卸载与发行链

1. 无线麦的安装包同时包含 SayAll 主程序、Siri Remote helper 和历史命名分支，不能逐字复制成独立声卡安装包。参考其固定版本的 PKG 构建、架构选择、载荷身份验证、安装回滚、音频服务加载及卸载思路，在本仓库重新实现只针对 TapSay 驱动的入口。
2. 只生成一个 Apple Silicon `arm64` DMG，内含 TapSay Audio 安装 PKG、单独卸载入口及中文说明。实现包含安装与卸载脚本；用户双击入口可操作。卸载入口沿用先前确认的独立 APP 体验，但其实现从新脚本构建，不复制旧 Swift 事务工具。构建与检查入口拒绝将 `x86_64` 当作本轮发行目标。
3. 安装只操作 TapSay 自有路径、Bundle ID 和收据；允许新版、同版、旧版覆盖。替换期间临时保留旧 TapSay 驱动；失败恢复，成功清理临时材料；恢复失败则保留唯一可追溯材料并明确报告。不得碰 MiRemoteV、BlackHole 或 TapSay 主程序。
4. 卸载脚本移除 TapSay 自有驱动、旧版可核验归属的历史安装材料和收据，确认设备 UID 从 CoreAudio 枚举消失才报告完成；设备仍存在时提示手动重启。未知身份对象、未完成事务及恢复材料保留。不改用户默认输入、输出和提示音设备。
5. 首次加载与旧版覆盖分别核对设备实际名义率及输入输出物理/虚拟流格式。旧系统设置可能把同一 UID 恢复至 16 kHz；不得以驱动编译默认 48 kHz 代替读回结果。若发生，先保存证据，按 CoreAudio 正式接口做仅针对 TapSay 的格式迁移并验证；不直接编辑系统全局 plist，不静默修改其他设备。
6. 保留 BlackHole GPL 全文、原始版权、无线麦参考来源、TapSay 修改清单及可重建源码。源码归档包含构建和安装脚本、配置及许可，不夹带构建缓存或把二进制误当源码。不得拷贝无线麦专有 Logo/Icon。未取得 Developer ID 账号时可构建本地未签名测试包，正式发布必须签名、公证并核对下载字节。

### 4.3 仓库清理

1. 在删除前保存当前提交、受影响文件清单和必要故障证据索引。保留 Git 历史；不执行历史重写或硬重置。
2. 新实现与安装包验证完成后，移除旧 `TapSayAudio.c` 派生文件、旧工程、`legacy`/`reference-16k` profile、实验构包脚本、旧原生事务实现以及对应无用测试。任何仍被新构建引用的文件先迁移，再删除旧入口。
3. 将仍有效的稳定身份、安装卸载体验、许可、支持范围和未完成真机验收写入精简现行 README、产品规格和验证状态。移除工作树中过期讨论、PRD 及阶段日志前，修复所有脚本与文档链接。特别消除构包脚本读取历史实施记录、源码归档打包整个旧实施目录的依赖。
4. 对 `.build/` 与 `dist/` 做路径、大小、散列和用途清单。只清理已确认可重建的旧缓存及过期实验包。真实故障证据、安装前备份与恢复材料在真实验收完成前保留；仓库清理不触及系统已装驱动。

## 5. 测试与通过条件

自动测试针对可观察结果：参考源码/补丁散列、`arm64` 有效构建设置与架构、主及隐藏设备 UID/枚举、完整且有序的 13 项率表、初始 48 kHz、输入输出双声道 Float32、USB 主设备/Virtual Box、数组容量边界、插件工厂、签名状态、PKG 载荷身份、覆盖回滚、卸载设备消失状态。新测试不得仅复述生成常量；隔离根目录测试不能冒充真实系统验收。

真实验收先记录固定主程序、RC003、输入法、两张声卡、系统版本、安装驱动二进制散列与运行实例。每次选择设备、冷启动、探测前后均读取实际率与输入输出格式。先在当前已装 MiRemoteV 记录同条件对照，再对新 TapSay 候选执行：冷启动至少 10 轮、MiRemoteV→TapSay 切回至少 20 轮、连续运行至少 60 分钟且每 15 分钟测试 5 次、长按边界与快速释放、16/44.1/48 kHz 独立环回、目标第三方输入法实际文字上屏。记录成功与失败样本、时间、日志、真实音频到达和触发键按下/释放。

首个可接受基线须在**设备实际运行 48 kHz**条件下通过真实切回和语音链路；任何播放探测超时都保留现场并暂停“已解决”结论。如果设备仍在 16 kHz、加载版本不明或未完成样本量，分别标为条件不满足或未验收。Intel 真机验收不属于本轮门槛，因为本轮不支持 Intel。不能仅凭参考源码相同、设备可见、短时成功或合成回环宣称稳定。

## 7. 范围与后续

- 本轮只在本仓库重新实现独立虚拟声卡；读取无线麦仓库作参考，不修改其代码。
- TapSay 主程序的音频图暂不在本轮改动范围。参考无线麦的播放器源为 16 kHz 单声道，经混音节点连接设备；需要跨仓库改图时，先用真实对照证据说明差异和必要性。
- 首个候选不做 16 kHz 默认值对照，不收缩参考采样率列表，不删除隐藏设备，不调整延迟、缓存或播放恢复策略。
- Intel `x86_64` 构建、安装包、真机验收和正式支持声明留待后续独立规划。
- 不覆盖 MiRemoteV/BlackHole，不自动更改系统默认设备，不直接改系统音频 plist，不自动重启 Mac。
- 旧 PRD 与旧验证记录是历史材料，不能继续作为新驱动的实现规范；仍有效的产品承诺必须迁入本 PRD 或现行产品说明。

## 10. 安装与卸载的状态合同

安装 PKG 文件名为 `TapSayAudio-2ch-0.1.0.pkg`，外层 DMG 为 `TapSayAudio-2ch-0.1.0-arm64.dmg`；正式版本号以后从唯一产品配置读取，不能在脚本里复制另一份常量。DMG 另含 `卸载 TapSay Audio.app`、中文说明、GPL 与第三方来源说明；发行目录还须有完整对应源码归档和 `SHA256SUMS.txt`。单架构二进制通过 `lipo -archs` 读回恰好 `arm64`，通过 `vtool` 核对 macOS 14.0 下限。

参考无线麦的组件包做法：PKG 载荷先放在 `/Library/Application Support/TapSay Audio/Installer/TapSayAudio.driver`，`preinstall` 只执行架构、系统及旧目标身份预检；`postinstall` 对暂存驱动做完整核验并移入 HAL，完成后清理暂存目录。独立声卡包不含 `/Applications/SayAll.app`、Siri Remote helper 或无线麦收据。安装和卸载脚本都应先在专用临时根目录执行故障注入，再进入真实系统测试。

安装流程按顺序执行：

1. 预检主机为 Apple Silicon、系统至少 macOS 14、候选载荷签名和架构有效；目标路径若存在符号链接、未知 Bundle ID 或异常文件，停止并保留原样。目标是已知旧 TapSay 时允许任意版本方向的覆盖。
2. 包内驱动先暂存于 TapSay 专属安装目录；进入 HAL 前再次验证 Bundle ID、工厂、UID、可执行文件、架构、版本和包内散列。并发安装/卸载使用同一独占锁。
3. 将旧驱动移到同一文件系统的临时事务路径，再将新驱动放入固定 HAL 路径；校验落地载荷。若复制、权限或签名校验失败，把新载荷移离目标并恢复旧驱动。恢复失败保留旧载荷的准确路径和错误报告，不能继续覆盖或删除它。
4. 驱动文件提交成功后清理临时旧驱动及暂存材料。清理失败时保持新驱动，报告剩余路径和“待清理”，不能把已提交的新驱动回滚成旧版，也不能报告完全成功。正常安装不留长期 `backup.driver`。
5. 提前告知用户系统音频可能短暂中断。尝试按参考方式重载音频服务后等待设备重新枚举；重载失败或设备仍是旧实例时报告“需要重启”，不自动重启。安装完成的含义分开记录为“文件已部署”和“音频链路已确认”，不能合并。
6. 对旧版本同一 UID 的持久 16 kHz 格式做定向检测；若设备实际未达 48 kHz，用 CoreAudio 正式接口仅对 TapSay 主设备申请 48 kHz，再读回名义率及输入输出物理/虚拟格式。读回成功仍需跨音频服务重载和整机重启验证持久性。若仍恢复 16 kHz，本阶段记录阻塞并停止发行，不直接删除系统 plist，不假装首装成功。

卸载 APP 先显示会删除的 TapSay 项和可能的音频中断，用户取消时不执行有权限操作。确认后调用包内固定的特权工具/脚本；不把设备名、用户可控路径直接拼进 shell 命令。卸载流程按顺序核对当前目标的 Bundle ID、收据和事务状态，只删除本产品驱动、安装状态与收据；旧版 `Library/Application Support/TapSay Audio/` 中的 `backup.driver` 及相邻状态文件，只有在身份、目录内容与事务状态都核验后才清理。无法核验归属的对象保留。设备移除后等待 CoreAudio 枚举结果：UID 消失才显示“卸载完成”；仍存在则显示“需要手动重启”；枚举不可用显示“无法确认”，都不能显示成功。若旧事务存在待恢复材料，先保证可恢复性再执行；安装、卸载并发必须被锁拒绝。成功卸载不留下新的长期备份。卸载一次、再卸载一次，以及旧版覆盖后卸载均需验证。

独立卸载工具向 APP 的标准输出仅输出一份 JSON 结果，诊断日志写标准错误；最少包含 `status`、`driver_absent`、`receipt_absent`、`device_status`、`remaining_paths` 和用户可读中文消息。APP 检查字段组合，不得仅凭脚本退出码 0 或“已请求卸载”显示成功。结果组合：全部文件/收据消失且设备消失为 `removed`；文件已移除但设备仍在为 `restart_required`；无法查询设备为 `unverified`；任何归属/移动/恢复失败为 `failed`。

## 14. 待批准补充：控制列表计数与读取边界

2026-10-21 对冻结参考与 TapSay 最小派生源码执行 AddressSanitizer HAL 回调测试，两者均在主设备的 `kAudioObjectPropertyControlList` 正常查询中触发 `global-buffer-overflow`。默认 `gPitch_Adjust_Enabled=false`，大小回调声明六项控制对象，读取回调跳过关闭的 Pitch 后只有五项，却继续遍历以凑足六项，最终读过 `kDevice_ObjectList` 边界。按驱动自己声明的大小请求即可触发；不需要异常参数。详见 `docs/implementation/2026-10-21-hal-control-list-blocker.md`。

这是前三项已批准修复之外的新增发现。现行构建与安装包不应用本节候选。批准本节后，才可将 `third_party/blackhole/proposals/control-list-safety.patch` 作为第四项正确性修复纳入驱动构建：

1. 主设备控制项计数排除关闭的 Pitch；大小回调在状态锁内读取计数。
2. 控制项读取同时限制对象数组长度和用户提供的容量；按请求的 global/input/output scope 筛选。
3. 同一个状态锁快照内读取 Pitch 状态、筛选并复制；返回实际写入字节数。隐藏设备保持自己的控制对象列表。
4. 不修改 IO、时间戳、采样率、缓冲、音频格式或混音算法。源码差异和测试报告单独保留。

批准后的验收：主/隐藏设备 × Pitch 开/关 × global/input/output × 容量 0 字节、1 字节、一个对象、准确容量、过量容量，共 60 项，核对返回对象顺序、实际字节数及尾部哨兵；AddressSanitizer 无越界。13 项率表、双声道 Float32 和初始 48 kHz 对照仍通过。候选已在独立进程通过这些用例，但尚未获准进入交付基线。
