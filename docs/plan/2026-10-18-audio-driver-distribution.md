# TapSay Audio 独立虚拟声卡 PRD

讨论日期：2026-10-18 至 2026-10-19

状态：用户已于 2026-10-19 批准；按阶段实现中
计划首版：0.1.0

评审补充：2026-10-19 根据社区报告及参考项目补丁，修订 transport type 兼容方案和豆包设备列表验收。用户已于 2026-10-19 批准本 PRD 全文及全部阶段实现。

## 问题陈述

TapSay 将小米遥控器语音送给第三方软件，需要稳定、可识别的虚拟声卡。当前独立仓库只有说明与许可文档，没有本项目驱动或可下载的安装包。普通用户不应自行编译驱动或手动操作系统 HAL 目录。

本项目需要独立完成驱动、构建、安装、覆盖更新、卸载及发布，并交付真实设备标识和下载入口。兼容性必须覆盖音频实际传输，而非只检查系统里出现设备名称。

## 解决方案

提供显示为 `TapSay Audio 2ch` 的双声道虚拟声卡。支持 macOS 14 及以上，Intel 和 Apple Silicon 分架构构建和发行。默认 16 kHz，同时提供 44.1/48 kHz 兼容能力。

每个架构提供一个 DMG，内含 PKG 安装包、独立 APP 卸载工具及说明。用户双击相应入口并授权即可操作；项目同时维护安装、卸载脚本。支持新版覆盖旧版、同版修复和旧版覆盖新版，失败时尝试恢复安装前版本。

采用 GPLv3 开源路线，通过本仓库 GitHub Releases 发行安装包、对应完整源码及校验文件。正式包发布前完成许可材料、签名、公证和对应架构真机验收。

### 安装和版本行为

- 新版、同版、旧版安装包均允许覆盖当前版本，不因目标版本较低而拒绝安装。
- 展示当前版本和目标版本，版本比较只用于说明和记录。
- 每次覆盖前备份安装前版本，失败时尝试恢复该版本；降级失败应恢复到安装前的较新版本。
- 需要管理员权限的操作走正常系统授权，取消授权应结束操作并给出准确状态。
- 安装不主动改变系统默认输入、输出、提示音设备，不创建聚合设备或多输出设备。
- 不修改 TapSay 用户配置，不自动替换其他品牌声卡，不根据相似名称删除文件。
- 音频可能中断前提示并允许取消。以无需重启为目标，不承诺所有环境都能即时生效。
- 需要重启时显示“需重启后生效”，由用户决定时间，不自动重启 Mac。

## 实施决策

以下技术默认设计、模块划分及测试范围随本 PRD 一并提交审批，不表示已全部作为单独问答获批。

### 术语和数据方向

- `TapSay Audio`：本项目与发布品名称；`TapSay Audio 2ch`：系统和应用中的唯一用户可见设备名称。
- HAL 驱动：运行在 macOS CoreAudio 中、向应用提供虚拟音频输入/输出端点的软件组件。
- 传输类型：系统查询的设备属性，不是连接器形态。本设计拟报告 USB 类型，以兼容报告中会隐藏 Virtual 类型设备的应用；用户不需要 USB 硬件。
- TapSay 写入方向：TapSay 选择此设备作为音频输出，向声卡写入遥控器声音。
- 第三方接收方向：QuickTime、豆包或微信输入法选择此设备作为麦克风/音频输入，从声卡读取 TapSay 写入的声音。
- CoreAudio 输出流：此设备面向系统播放/写入客户端的一侧；TapSay 的音频引擎向该流提交采样。
- CoreAudio 输入流：此设备面向录音/读取客户端的一侧；第三方软件从该流取得 TapSay 已提交的采样。
- “设备已枚举”：CoreAudio 返回正确 UID 和设备名。
- “设备可选”：目标软件将它显示为可选输入。系统能枚举不等于软件可选。
- “链路通过”：目标软件读到本轮 TapSay 实际发送的有效音频。只看到设备、引擎启动、静音波形或内置麦克风文字输入都不算通过。
- “驱动已就绪”：安装后 CoreAudio 已重新枚举到规定 UID，设备名、方向、公开格式和必要属性符合合同。此状态不等于已验证真实音频传输或任何第三方软件兼容。
- “覆盖升级”：在当前驱动仍安装时直接运行另一个版本安装包，安装器替换本项目驱动；不先让用户手动卸载。

开发报告每个阶段必须分别写出：已交付产物、执行验证、逐条通过/失败、未覆盖平台、剩余发布阻塞。不要用“看起来正常”“构建成功”代替观测数据。

| 诊断与验收工具 | 读取真实 UID/格式、探测音频、生成环境记录 | 可观察信号与实际设备匹配 |

安装与卸载共用受限的文件操作与状态检查逻辑，避免两个入口各自实现不一致的清理规则。测试验证对外行为，不绑定函数拆分或内部调用次数。

模块接口约束：

1. **项目元数据**是唯一标识来源；驱动、Info.plist、PKG 收据、卸载 APP、DMG、README、主程序对接清单都从同一版本元数据产生。构建后逐项反读成品比较。
2. **HAL 驱动**只负责虚拟音频端点、CoreAudio 属性和两向音频环回，不安装、不删除、不自行重启 Mac。
3. **安装事务**负责识别主机、授权、备份、安装调用、生效检查、恢复及最终结果；不能静默假定“脚本退出 0”即声卡可用。
4. **卸载 APP**显示清理范围和最终结果；真正有权删除系统目录的代码限制为窄范围的卸载操作，不以 root 身份运行整个 UI。
5. **验收探测器**区分找 UID、核实名/transport/格式、核实可录输入、核实真实数据；各检查失败码彼此区分。
6. **发行打包器**接收单一已验证的驱动产物，产生两个分别标记架构的资产及同版本源码，不重新编译出未被检查的第三份驱动。

### 驱动属性与应用兼容

- 用户可见 CoreAudio 设备只有一个，不创建用户可见的第二设备、镜像设备、聚合设备或多输出设备。该设备应有一个双声道输出流供 TapSay 等客户端写入，以及一个双声道输入流供第三方软件读取；这里的输入/输出方向均以 CoreAudio 客户端视角命名。
- 输出流数据进入环形缓冲，输入流从对应缓冲读取；读空时返回静音采样而不是未初始化内存，写入及读出跨边界必须正确处理。
- 首版只公布三个采样率：16,000、44,100、48,000 Hz。默认初始值 16,000 Hz。对三个数值均须正确读写属性、通知 CoreAudio 变化并在变化后继续传输。
- 流格式采用双声道、32-bit Float PCM，使用平台规范的字节序及打包标记。驱动 CoreAudio stream format 与 AVAudioEngine 客户端格式分开检查；客户端是否需要 non-interleaved 由实际 TapSay 链路决定，不将一个层的格式描述冒充另一个层。
- 遥控器音源为单声道，而声卡固定双声道。通过输入端分别检查左右通道实际数据。TapSay 语音在两侧均可被目标软件接收；若主程序直连只产生一侧数据，记录结果并先更新 PRD/主程序审批，不把所有立体声任意复制或混音塞进驱动。
- 按主程序当前 `VirtualAudioConfiguration` 配置行为，设备必须暴露可读写的输入静音、输出静音、输入音量和输出音量控制。初始值分别是未静音及音量 `1.0`；对写入执行回读验证。TapSay 不应因控制缺失导致设备被自动配置流程永久判失败。
- 不增加降噪、回声消除、自动增益、语音识别或其他音效。
- 实际设备 UID 必须精确匹配 `com.leafney.tapsay.audio.device.2ch`；不能只改显示名称或编译目标名称。Box UID、Model UID、所有隐藏对象 UID 各自唯一、固定、属于本项目且不能与已有产品冲突。
- 插件工厂 UUID 必须项目自有、稳定且在注册表与 `CFPlugInFactories` 中一致。不得照搬 MiRemoteV/BlackHole 的工厂 UUID。Apple 标准 `CFPlugInTypes` 接口类型 UUID 保持原值。
- 优先使用主程序现有直连输出链路。Apple 输出节点自身可转换格式，不能仅因参考项目使用混音节点就强制改图。
- 根据社区报告及参考项目源码，首版拟将设备的 `kAudioDevicePropertyTransportType` 上报为 `kAudioDeviceTransportTypeUSB`，作为豆包等软件可能过滤 Virtual 类型的兼容处理。这取代初稿“先保留 Virtual”的设计，须随本 PRD 获批后实施。
- USB transport type 只用于设备属性兼容，实际仍是软件虚拟声卡，不要求用户连接 USB 硬件，也不改变设备 UID、名称、采样率或系统默认路由策略。
- 只参考 transport type 的兼容改法，不复用 MiRemoteV 工厂 UUID、名称或 Bundle ID；各项目标识仍遵守本 PRD 独立身份合同。
- 评论者所述过滤原因不是已获得豆包官方确认的通用规则，源码补丁只证明参考项目采用该方案，不证明 TapSay 已通过兼容验收。具体软件版本须实测列表、选择及音频传输；其他过滤因素或权限故障单独排查。
- 安装、卸载或格式变化后重新读取设备事实；旧 AudioDeviceID、旧回调或名称缓存不能代替重新枚举的 UID。

USB 兼容方案具体实施及检查步骤：

1. 修改设备的 transport type 属性返回为 CoreAudio 的 USB 类型常量。不要伪造 USB 厂商、产品、序列号或物理连接对象。
2. 构建后通过 CoreAudio 实际枚举读取 transport type；应同时看到指定 TapSay UID、规定设备名、双向流和三个采样率。
3. 在豆包实测版本中打开麦克风列表并截图/记录。本设备必须出现在列表；选择后保持选择并实际录到 TapSay 输入。记录豆包是否自动切换设备格式。
4. 若设备仍不出现，先读取实际 transport type 及权限、软件版本；归类为 transport 值未生效、软件过滤规则不同、权限拒绝或未知原因，禁止悄悄再改制造商名、设备名、厂商 ID/产品 ID或增加另一套虚假设备。
5. 若必须更改新的硬件属性才能兼容，提供最小复现和属性读数，更新本 PRD并等批准。

### 安装事务与故障恢复

按“预检 → 加锁 → 备份 → 部署 → 检查 → 提交结果”的顺序处理。安装与卸载不能并发修改同一实例，重复点击不得产生多份事务。

| 阶段 | 输入和动作 | 成功结果 | 失败行为 |
| --- | --- | --- | --- |
| 预检 | 读取实际 macOS 版本、主机架构、包架构、驱动身份/版本、目标位置、载荷校验值、当前安装状态、权限可用性 | 生成安装计划；所有会改动的 TapSay Audio 专属内容列在计划内 | 不触碰已有文件，显示可读失败原因 |
| 确认 | 显示安装/更新/重装/降级类型、目标版本及可能音频中断；请用户继续或取消 | 取得用户确认 | 取消即退出，状态不变 |
| 加锁 | 获取本项目安装状态锁 | 此安装事务为唯一活动修改者 | 锁忙时告知用户另一操作进行中，不并行破坏 |
| 备份 | 有旧版时备份当前驱动、收据信息与恢复所需元数据；首次安装创建清洁事务记录 | 备份完成并可检查 | 备份失败停止，原版本不变 |
| 部署 | 仅删除/替换已核验为本项目 UID、Bundle ID、收据所有的目标；写入预检通过的架构和版本 | 文件落盘、权限和签名状态符合预期 | 立即转入失败清理或回滚 |
| 生效检查 | 重新枚举 CoreAudio 设备，读取 UID、名称、transport、输入输出流和支持格式；在不改变用户路由的前提下检查属性可读写 | 若设备身份及必要属性符合合同，显示“驱动已就绪”；真实数据传输状态单独显示为“未验证”，直至独立链路验收通过 | 只有驱动未出现、身份错误或必要属性不符等驱动级失败才回滚；不得因第三方软件权限、设备选择或语音识别结果回滚 |
| 完成 | 记录当前版本、备份位置、架构、测试结果和重启状态 | 清楚显示完成，保留用户选择和系统路由 | 无法确认即显示待处理，不猜测成功 |

版本规则不参与预检拒绝决策：目标 `<`、`=`、`>` 当前版本均允许进入确认流程，前提是载荷架构、签名、身份和格式满足合同。降级失败必须还原进入事务前安装的较新版本。

预检包含实际主机架构、系统版本、目标位置、载荷身份与完整性、磁盘或权限错误。Apple Silicon 上运行在兼容环境中的进程架构不能直接代替真实主机架构判断。拒绝错误架构、无效载荷或身份不明的目标，不把这类拒绝误写成禁止降级。

备份包含当前驱动和恢复所需版本、所有权及收据信息。只对确认为本项目所有的目标操作；目标路径、符号链接及已有内容异常时，在破坏前停止并说明原因。

部署或可即时完成的加载检查失败时尝试恢复，并重新检查恢复结果。恢复失败保留唯一可用备份与故障记录，提供人工指引，不自动删除备份或假报成功。首次安装没有备份时，只清理本次产生的专属内容，报告实际残留。

至少区分：用户取消、预检失败且未修改、部署失败并已恢复、恢复失败待处理、部署完成待重启、驱动已就绪、音频链路未验证/已验证。安装界面不得把“驱动已就绪”显示成“真实音频链路已验证”。第三方软件权限、网络识别服务、软件内设备选择或识别结果失败不触发盲目驱动回滚。

### 卸载体验

- 提供独立可双击 APP，执行前列出清理内容并确认，内部调用本项目卸载逻辑。
- 只删除经身份核验的本项目驱动、专属安装内容和必要收据。不删除主程序、用户音频配置、其他声卡或系统通用目录。
- 重复卸载应报告当前未安装，不能将不存在视为需要扩大清理范围。
- 只完成文件清理但设备仍待系统释放时，报告真实待生效状态；不把系统尚未释放的缓存实例视为文件仍在。
- 失败恢复备份的保留与清理必须显式区分，不默认删除唯一恢复来源。
- 允许系统在移除当前使用设备后自行选择可用设备；工具本身不强制设置新的系统默认路由。

卸载 APP 操作顺序：显示设备名、版本和清理清单 → 用户确认 → 获取完成系统目录修改所需授权 → 验证目标确为 TapSay Audio → 删除专属载荷与收据 → 重新枚举确认该 UID 已消失 → 展示成功/部分残留/未安装。取消或授权拒绝时不得开始删除。不能对通配符路径、相似名称或整个 HAL 目录运行递归删除。

### 分架构包装与发布

首版外层资产设计为 `TapSayAudio-2ch-0.1.0-arm64.dmg`、`TapSayAudio-2ch-0.1.0-x86_64.dmg`。每份内含 `TapSayAudio-2ch-0.1.0.pkg`、独立卸载 APP 和中文说明。同名 PKG 的架构以实际载荷及安装预检为准。

用户给出的内层 PKG 名称完全保持 `TapSayAudio-2ch-0.1.0.pkg`。两个文件分别存在于不同架构的 DMG 内，不给 PKG 文件名自行加架构后缀。外层 DMG 使用 `arm64` 和 `x86_64` 后缀。卸载 APP 的显示名为“卸载 TapSay Audio”；其 Bundle ID 使用既定合同。

首版不增加统一安装卸载管理器、常驻更新服务或自动下载安装。正式发行通过本仓库 GitHub Releases，每个架构分别满足门槛，不将未验收的 Intel 包随 Apple Silicon 包标为已通过。

开发验证可在用户尚未提供账号证书时推进，开发包清楚标记状态。正式发行需要用户提供 Developer ID 相关签名和公证条件，再对实际交付载荷、PKG、卸载 APP 与外层分发容器执行适用检查。不得把临时签名冒充正式签名。

README 与发行说明标明版本、各架构、实测系统及软件版本、签名公证状态、已知问题、对应源码及校验方式。真实下载地址在已发布资产可获取且验证后交付，不提前伪造。

发布前自动清单至少核验：两个 DMG 各自只有预期架构载荷；PKG 的收据标识正确；HAL Bundle ID、设备 UID 和显示名正确；卸载 APP 标识正确；没有 BlackHole/MiRemoteV 产品名、上游开发者 Team ID、上游图标或意外隐藏镜像端点；GPLv3及上游版权/品牌声明材料齐全；源码包版本和散列匹配对应安装包。

### 真机与第三方验收

默认 16 kHz 是首要路径，44.1/48 kHz 分别复测。每轮记录软件启动前后的实际设备格式；导出录音文件格式不能替代设备运行格式。

| 范围 | 通过条件 |
| --- | --- |
| 干净安装 | 正确设备和版本出现，真实音频链路可用，系统默认路由未被安装器主动改写 |
| 覆盖与降级 | 三类覆盖均可执行，身份稳定，失败恢复状态准确 |
| 卸载 | 只移除本项目内容，保留其他设备和用户配置，实际残留如实报告 |
| 格式和声道 | 16/44.1/48 kHz 可实际工作，TapSay 单声道来源接收正常，时长和音高正确 |
| QuickTime Player | 明确选择本设备后录制、回听有效遥控器声音 |
| 豆包、微信输入法 | 按实际版本核实设备选择方式；豆包提供麦克风列表时，本设备必须可见、可选、选择可保持，并实际收到音频；实际语音触发、释放、文字输入及重复使用正常 |
| 来源对照 | 停止向声卡送音频时，不因实际使用内置麦克风而假通过 |
| 运行变化 | 设备重枚举、格式变化、休眠唤醒及接收软件重开后可用或明确报错并可恢复 |
| 多设备共存 | 与既有 MiRemoteV/BlackHole 同机，安装卸载互不覆盖身份及文件 |

识别文本不要求逐字完全一致，不承诺识别准确率；账号、权限、网络、服务及快捷键故障与驱动问题分开记录。运行日志不保存用户说话内容和输入文字；留存验收样本使用明确的专用测试内容。

对应用提供设备列表的版本，不能仅通过修改系统默认输入或 QuickTime 录音成功来绕过“列表不可见、不可选”的失败。若实际版本只提供自动检测，单列该模式验证实际来源和限制，不将其假报为显式选择通过。问题报告至少区分设备未列出、不能选择、选后无音频和音频格式异常。

当前用户仅有 Apple Silicon 真机，优先完成该架构验收。Intel 可先构建及静态检查；Intel 真机安装、升级、降级、卸载及音频验收是对应正式包发布前依赖。不得用交叉编译或兼容运行代替原生 Intel 真机验收。

不承诺未经验证的“零延迟”或整条链路固定延迟。记录本次环境的实际首段、连续语音和释放表现；明显吞音、变速、持续断音或无法恢复视为不通过。
