# 卸载调用与结果判断修复

日期：2026-10-19
关联规格：`docs/plan/2026-10-18-audio-driver-distribution.md` 的“卸载体验”及生效状态合同。

## 故障及原因

用户执行包内卸载入口后，系统输入输出仍显示设备；没有看到要求重启的提示。

只读检查确认驱动目录、安装收据和实际设备 UID 均仍在。源码中的卸载界面直接调用事务程序，但传入的是供界面内部使用的 `--privileged-uninstall`，没有传入事务命令及资源配置路径。事务默认从自身同目录寻找配置，实际配置却位于 Resources 中。

提权 API 启动成功不代表子程序卸载成功。旧界面依赖输出文本识别失败，且将空输出解释为已执行；旧事务也没有实际枚举验证设备消失，只根据刷新音频服务命令是否退出成功选择提示。

## 修复

- 共用明确的事务参数：`uninstall --yes --metadata <Resources/product.json> --uninstall-report`；不以管理员身份运行图形界面。
- 事务返回带版本、命令、UID、文件/状态/收据是否不存在、设备状态和终态的 JSON。界面检查协议及内部一致性，不再猜测文本或以空响应为成功。
- 失败路径也输出结构化失败；授权失败、配置缺失、未知命令、空响应和无法解码的响应不能显示卸载完成。
- 清理后回查驱动和状态文件，重新读取收据清单。读取收据清单失败与收据不存在分别处理。
- 实际枚举所有设备 UID；列表或任一必要 UID 读取失败时保守显示无法确认。约五秒内连续两次目标 UID 不存在才确认移除，避免短暂列表变化造成误判。
- 设备仍存在时明确要求保存工作、手动重启 Mac 后复查。无法读取设备状态时显示待确认并给出同样的重启后复查指引。工具不自动重启。
- 已无文件和收据但设备仍在的重复卸载也会检查实际设备，不能直接报告未安装。
- 只清理原本约定的专属目标，保留恢复备份及其他声卡；未修改主程序、设备默认值或原设备身份。

## 验证

- 两种架构原生工具编译通过。
- `python3 scripts/test-native-transaction.py` 通过：包含原有安装/回滚/符号链接保护，以及共享卸载参数的真实临时目录清理、重复卸载、缺少确认、配置缺失和旧错误参数的结构化失败。
- 协议与状态测试通过：空/错误/自相矛盾响应、文件残留、设备存在、无法枚举、稳定消失、瞬间消失及截止边界。
- 沙箱外只读 `UninstallResultTests --device-status` 返回 `present`；本机目标 UID 尚在。沙箱内查询返回 `unavailable`，不被解释为不存在。
- Python 语法、Shell 语法和差异空白检查通过。
- 分架构 PKG/DMG 构建与 PKG 内容检查通过，两个 DMG 完整性检查通过；只读挂载确认内嵌卸载界面、事务二进制与当前构建逐字节一致，架构、资源及新版卸载说明正确。
- 直接运行 arm64 镜像内实际事务程序，以共享界面参数在临时目录执行安装及卸载，通过；没有实际修改系统 HAL。Intel 镜像仅完成静态检查。
- 本地发行检查继续列出未签名、公证、真实卸载及 Intel 真机等未满足条件；不作为正式发布包。最终资产散列以 `dist/SHA256SUMS.txt` 为准。
- 最终检查发现同名旧镜像仍有系统挂载记录，原路径可返回“资源暂时不可用”。校验器改为验证当前字节的独立副本，不推出用户卷；另外提供带 `-uninstall-fix` 后缀、与标准镜像逐字节相同的修复镜像，避免打开旧挂载实例。

## 用户实测与限制

本轮未执行真实管理员卸载、未删除本机驱动、未清理本机收据、未重启 coreaudiod 或系统。真实卸载尚未验收。

实测时先退出使用该设备的音频程序，推出旧版 DMG，打开 `dist/TapSayAudio-2ch-0.1.0-arm64-uninstall-fix.dmg`，运行其中的“卸载 TapSay Audio.app”。无需为更新卸载工具重新安装声卡；旧挂载镜像内的工具不会因磁盘同名 DMG 被重建而自动更新。修复副本散列见 `dist/UNINSTALL-FIX-SHA256SUMS.txt`。

请记录最终提示；代理负责重新核对驱动目录、收据和实际 UID。提示待重启时保存工作并主动重启，再检查 UID。若仍有残留，继续分析，不反复执行扩大范围的删除命令。

卸载仍使用已弃用的 Authorization Execute 接口，真实授权路径尚待实测；迁移特权辅助机制不属于此次缺陷修复。当前开发包未签名、公证，Intel 仅完成构建及静态检查，不代表 Intel 真机卸载通过。

用户确认主程序由另一会话并行修改；本修复只在声卡仓库提交，不读取并处理那些并行改动。
