# 参考实现一致性复核

日期：2026-10-20
对应规格：`docs/plan/2026-10-20-driver-reference-baseline.md`
状态：发现未充分披露的行为差异，当前包不能认定已完成严格参考一致性验收。

## 用户纠正

用户要求先将驱动代码和配置按无线麦参考实现对齐，再验证是否复现；
不是在尚未核实一致性的情况下，继续修改运行采样率或扩展恢复策略。
本轮停止系统采样率变更计划，优先处理实现一致性。

## 复核方法与范围

对固定 BlackHole 提交的 C 源码及无线麦构建脚本、USB 补丁进行本地只读对照。
去掉注释与空白、规范化源码前缀后比较，保留原始文件和实际差异以便复核。
名称替换仅用于辅助阅读，不把名称不同直接判为音频行为不同。
同时抽查 arm64 Release 的有效构建参数。

本次不修改驱动、主程序、系统音频设置，不安装新包。
也不把源码差异直接认定为目标超时的原因。

## 已明确允许的差异

PRD 第 6.3 节允许自有产品身份、制造商、独立隐藏设备身份、
去掉未采用的品牌图标及伪序列号、OwnedObjects 索引安全修复、
本项目最低系统支持边界和许可材料。

配置入口与生成头文件属于实验追踪机制，必须证明展开后的有效配置符合参考，
不能仅因 profile 名为 reference-48k 就认定一致。

## 发现的额外行为差异

| 位置 | 固定参考行为 | 当前行为 | 影响与结论 |
| --- | --- | --- | --- |
| `TapSayAudio_GetPlugInPropertyData` 的 UID→Box、UID→Device | qualifier 大小恰好等于 CFStringRef 大小时返回大小错误 | 改为大小不等时返回错误 | 修正了参考的反向校验；属于实际行为差异，此前未在允许差异表中明确列出 |
| 同函数 UID→Box | 匹配后还执行一次格式化 UID 比较 | 直接返回 Box | 产品身份实现变化与逻辑简化混合，不能仅标为改名 |
| `TapSayAudio_GetBoxPropertyData` 的 DeviceList | Box 已获取且容量小于一个对象时返回大小错误 | 容量为零时成功返回零项 | 属于边界合同变化，不能仅描述为恢复双设备枚举 |
| `TapSayAudio_GetDevicePropertyData` 的第二设备 ControlList | 用主设备对象列表的类型和音高校验条件筛选，读取第二设备对象列表 | 用第二设备对象列表自身的类型筛选 | 修正了参考列表筛选问题；也是未明确披露的行为差异，不能擅自判为与故障无关 |
| `TapSayAudio_SetDevicePropertyData` 名义率变更请求 | 请求配置变更的对象固定为主设备 | 请求对象为传入设备对象 | 对主设备请求结果相同，对隐藏第二设备请求语义不同；不属于单纯恢复第二设备可查询 |

另外，当前实现将多个设备对象条件抽为辅助函数，简化主/第二设备 UID 返回分支，
删除一个未使用的时间戳局部变量。这些属于代码文本差异；
与上表的可观察行为变化分别记录，不以差异行数推断风险。

## 构建核对的局限

首轮 arm64 有效设置抽查中，下列字段一致：

- 优化级别 `s`，`DEAD_CODE_STRIPPING=YES`。
- `COPY_PHASE_STRIP=YES`、`STRIP_INSTALLED_PRODUCT=YES`、`STRIP_STYLE=non-global`。
- `ONLY_ACTIVE_ARCH=NO`、架构 arm64、最低系统 14.0。
- Mach-O 类型 `mh_bundle`，调试信息格式 `dwarf-with-dsym`。

参考通过命令行传品牌和声道宏，当前通过生成头文件传入；
必须比较预处理后的有效值，不能要求两条宏传递字符串逐字相同。
本次抽查不是全部构建参数、两个架构或预处理后代码的完整一致性证明。

当前实验包清单的 `build_settings` 只有配置、架构、活动架构选项、
关闭签名和最低系统几个字段，未保存 PRD 要求的完整有效构建设置。
此前的实施记录没有提供足以复核“完整构建设置已对齐”的证据。
