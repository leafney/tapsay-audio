# 阶段 6：设备与音频链路验收

日期：2026-10-19
对应规格：`docs/plan/2026-10-18-audio-driver-distribution.md`

## 已完成的隔离验收

- 增加只读 CoreAudio 诊断工具 `Tools/Transaction/Diagnose.swift`，报告系统可见设备的 UID、名称、transport、输入/输出流、当前采样率和离散支持采样率。
- 增加 `Tools/Transaction/Loopback.swift`，在目标声卡上同时播放并采集左 1 kHz、右 1.5 kHz 的 Float32 合成 PCM，分别报告帧数、RMS、峰值和目标频率能量比例；采集样本只保存在内存、不写文件。
- 环回前切换并回读设备实际采样率，核对输入/输出流的虚拟、物理格式；结束后恢复原采样率。两个队列分别回读 UID，防止默认设备回退造成假通过。
- 诊断工具默认只读；显式使用 `--verify-controls` 时，对输入/输出静音和音量临时写值、回读并恢复，同时比较测试前后的系统默认输入、输出和提示音路由。
- 诊断工具以退出码区分 CoreAudio 查询失败、目标设备缺失和设备属性不符合合同，不修改系统路由或设备。
- HAL 回调测试调用真实 `StartIO`、PCM `WriteMix` 和 `ReadInput` 回调；验证双声道样本保持一致及环形缓冲区末尾回绕。
- `bash scripts/run-driver-contract-tests.sh`：通过。
- `bash scripts/build-native-tools.sh`：arm64、x86_64 诊断与 PCM 环回工具构建成功。
- Loopback 运行方式：`./.build/native/arm64/TapSayAudioLoopback [16000|44100|48000] [秒数]`。仅在 TapSay Audio 已安装且 CoreAudio 已枚举到设备后运行。

## 已安装设备自动验收

执行：`./.build/native/arm64/TapSayAudioDiagnose --verify-controls`。

| 控制项 | 测前值 | 临时测试值 | 回读与恢复 |
| --- | --- | --- | --- |
| 输入静音 | 0 | 1 | 通过，恢复 0 |
| 输出静音 | 0 | 1 | 通过，恢复 0 |
| 输入音量 | 1.0 | 0.5 | 通过，恢复 1.0 |
| 输出音量 | 1.0 | 0.5 | 通过，恢复 1.0 |

控制测试前后，默认输入、输出和提示音设备 ID 均保持一致。这不是安装前后的路由对照；安装前没有保存基线，不能据此断言安装全过程路由未变化。

执行：分别运行 `./.build/native/arm64/TapSayAudioLoopback RATE 3`。

| 请求/设备实际采样率 | 帧数 | 左/右 RMS | 左/右峰值 | 左/右目标频率能量比例 | 结果 |
| --- | ---: | --- | --- | --- | --- |
| 16000/16000 | 48964 | 0.17209 / 0.17209 | 0.25000 / 0.25000 | 0.94770 / 0.94772 | 通过 |
| 44100/44100 | 133072 | 0.17473 / 0.17472 | 0.25000 / 0.24999 | 0.97693 / 0.97691 | 通过 |
| 48000/48000 | 144944 | 0.17521 / 0.17521 | 0.25000 / 0.25000 | 0.98236 / 0.98234 | 通过 |

每轮输入/输出流的虚拟、物理格式均为本轮实际采样率、双声道、32-bit Float PCM；左侧 1000 Hz、右侧 1500 Hz 的独立频率检查通过。每轮恢复 16000 Hz。上述结果验证合成音频的真实 CoreAudio 环回，不代表 TapSay 单声道映射或第三方软件通过。
