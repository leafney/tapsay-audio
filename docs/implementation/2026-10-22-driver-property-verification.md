# 第三批属性修复验证记录

规范：`docs/plan/2026-10-22-driver-property-fixes.md`。用户已确认前两批人工测试无问题并授权第三批。前两批包及对应构建记录保留在 `.build/pre-third-batch-0.1.0/`。

## 阶段一：插件属性

- 固定上游文件不变，新增独立插件属性补丁：OwnedObjects 第二项索引为 1，两种 UID qualifier 大小判定为不等于。
- 明确补丁顺序、固定散列，参考审计先建立原样参考，再应用属性修复比较源码；未声明的差异仍失败。
- 独立进程 AddressSanitizer 合同通过 158 个用例，覆盖两种 Box 获取状态、对象列表容量 0 到 20 字节、Box/主/隐藏/未知 UID、空 qualifier、错误大小、输出容量及前后哨兵。
- 日志：`.build/third-batch-plugin-tests.log`。不访问运行中的 coreaudiod，不安装驱动。

## 阶段二：控制列表

- 从历史候选逐项核对形成正式控制属性补丁；保留旧候选及复现材料用于历史对照。修复主设备 Pitch 关闭时计数、读取 scope 筛选、数组遍历边界和隐藏设备误用主数组。
- 大小和数据回调分别持状态锁；数据回调仅按当前状态和实际调用者容量返回，报告真正写入字节数。
- AddressSanitizer 控制矩阵通过 1,312 个用例：两设备、四个 scope（含未知）、大小查询及读取时分别启用/禁用 Pitch、0 到 40 每一字节容量、返回顺序及前后哨兵。
- 日志：`.build/third-batch-control-tests.log`。源码审计通过；移除任一声明修复或擅改默认采样率都会被审计拒绝，变更/遗漏补丁散列也被拒绝。

## 阶段三：集成交付

- 产品配置已递增到 0.1.1/构建 2；UID、Bundle ID、工厂标识及平台范围不变。包内驱动、卸载 App 与内置元数据继续由同一配置生成。
- 构建记录增加四个正式补丁的散列；合同入口拒绝旧模式或补丁散列不符的构建记录，不接受另一个旧产物作为本次验证对象。
- 源码包包含两个正式属性补丁、固定散列清单、共享构建输入模块和完整 HAL/源码测试；发行检查强制要求这些文件存在。
- 生成后的 C 文件保留上游版权并增加本项目修改内容与日期说明；固定上游源文件仍未直接改写。
- README、DMG 说明及上游修改记录更新至第三批现状，历史候选仍不参与构建。
