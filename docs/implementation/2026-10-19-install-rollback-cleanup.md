# 安装回滚与历史清理实施记录

日期：2026-10-19
关联规格：

- `docs/plan/2026-10-18-audio-driver-distribution.md`

## 交付

- 安装事务不再创建长期 `backup.driver`。覆盖安装时只把旧驱动移动到本次 UUID 的 HAL `.previous` 路径，并保存旧状态副本。
- 新增严格事务记录，固定保存阶段、终态、部署结果、清理状态和残留路径；记录在每次文件移动前原子写入并回读核实。
- 安装成功提交后，仅清理本次事务的旧驱动、暂存驱动和状态副本。提交后的清理失败不会自动回滚新版本，而是保留 `committed + cleanup_pending` 记录供重试。
- 安装失败后按实际文件状态恢复旧驱动和旧状态。恢复成功时清理本次材料；恢复失败时写入 `recovery_required`，保留唯一旧驱动、旧状态和事务记录。
- 后续安装或卸载会先处理活动事务残留：已提交或已回滚事务只重试清理，不重复移动驱动；待恢复事务阻止继续操作。
- 新增旧版历史枚举。候选必须位于固定事务根目录一层、目录名是标准 UUID、`backup.driver` 是本产品普通驱动目录，且二进制、Bundle ID、设备 UID、插件工厂、插件接口和旧状态目标匹配。
- 未知对象、链接、越界路径、活动事务记录和 `recovery_required` 材料整体保留。删除按候选逐个记录，部分失败可直接重试剩余项。
- 卸载结果升级到 schema v2，新增 `cleanupStatus`、删除/剩余材料计数及剩余路径。旧 schema 1 被拒绝，不猜测兼容。
- 图形卸载入口删除“恢复备份会保留”的旧文案，并增加“只在安全确认归属时清理历史材料”的说明。

## 验证

- `bash scripts/build-native-tools.sh`：arm64 与 x86_64 事务工具、卸载界面和诊断工具编译通过。
- `python3 scripts/test-native-transaction.py`：通过严格事务记录解码、首装、同版重装、移动/部署/状态写入失败、恢复失败、异常中断恢复、提交后清理失败、回滚后清理失败、历史材料部分失败与保护、设备状态不明不删历史等隔离用例。
- `python3 scripts/check-uninstaller.py`：卸载 APP 标识、资源与双架构工具结构检查通过。
- `git diff --check`：通过。
- 隔离测试没有执行真实系统卸载、没有删除真实 HAL 驱动、收据、设备状态或本机历史事务目录。

## 限制

- 当前测试环境无法让 CoreAudio 对临时路径中的驱动返回 `absent`，因此卸载集成测试验证的是设备状态不明时保留历史材料；合法历史删除由独立临时根目录身份测试覆盖，但仍需真实卸载工具在用户授权下复测。
- 安装事务提交后的清理失败、异常进程中断和审计器模拟已覆盖主要状态，但不能替代断电、磁盘满、权限在单步操作中变化等真实系统故障演练。
- 真实系统历史材料可能来自旧版或其他架构；未在本次工作中删除。发布前仍须按 PRD 做用户授权的只读清单和实机复查。
