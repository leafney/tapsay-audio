日期：2026-10-21
状态：用户已纠正重建范围；配套 PRD 待批准，未开始实施。

## 原始需求

用户反馈：早期过度围绕遥控器的 16 kHz 源格式设计虚拟声卡，安装后持续遇到问题；同机使用无线麦的 MiRemoteV 2ch 没有同类现象。希望重新梳理项目，以无线麦的实现为参考，默认按 48 kHz 工作，并先给出实现规划。已授权读取本地 `../apps/remote-mic-app`，建议“推翻重来”以摆脱此前弯路。

用户补充：所谓“推翻重来”主要是清除开发过程中留下的无用文件、数据和文档，使最终成品目录简洁；不等于已经决定把安装、卸载等全部功能重新实现。

用户随后明确纠正：初衷就是推翻整个项目，先完整参照已经实测稳定的无线麦虚拟声卡方案，从零建立 TapSay Audio，再考虑任何优化。当前项目经历多轮修改仍有问题，不能继续把旧实现当成基线。48 kHz 实际输出条件下曾短时验证有效；不能再把遥控器 16 kHz 源格式用作声卡的默认运行率。

用户进一步指定：本轮在新分支 `feat/61021` 实现；首个交付只生成 Apple Silicon `arm64` 的 macOS 安装包，Intel 暂不支持。

用户再补充：PRD 会交给能力较弱的模型执行，需要逐文件职责、确切的构建与验收步骤、故障分支和清理边界，避免它自行猜测。

3. 问：“改成 48 kHz”是否指声卡首次加载默认并在实际使用时核验 48 kHz，还是还要求 TapSay 主程序主动固定输出节点为 48 kHz？建议遥控器源数据保持 16 kHz，由音频引擎完成格式转换。

4. 用户主动补充实施分支：`feat/61021`，不是沿 `feat/61018` 继续开发。
5. 用户主动补充架构范围：只交付 Apple Silicon `arm64` 安装包，Intel 暂不支持；因此首轮构建、包检查与真机验收均只针对 `arm64`。
6. 用户主动补充文档粒度：给后续编码者可执行的文件映射、状态合同、测试案例和阶段停止点。相应细节已写入配套 PRD 第 8 至 13 节。

## 代码与文件核对

- `tapsay-audio` 工作区干净，75 个已跟踪文件，其中 22 个在 `docs/`；文档总计约 3305 行。
- 本地 `.build/` 约 301 MB，已被 Git 忽略。其中驱动构建目录约 82 MB、原生工具构建目录约 186 MB，另有约 31 MB 的实验目录，内含真实故障证据与安装前备份；不能把所有内容一概视为缓存。
- `dist/` 当前是两个 `reference-48k` 实验 PKG 及校验和，尚非正式发行资产。
- 普通构建入口仍默认 `legacy`：默认率 16 kHz，仅声明 16/44.1/48 kHz。`reference-48k` 是实验配置，默认 48 kHz，声明固定上游的 13 项采样率和隐藏第二设备。
- 参考无线麦固定使用 BlackHole v0.7.1、提交 `e2b22aaaba4e507a097131704bf96dabc004d9cf`，其 USB 补丁只改主设备的 transport，并保持 Box 为 Virtual；构建还覆盖名称、Bundle ID 与声道数。
- 无线麦仓库当前 HEAD 为 `e1e74d49ff192576c4805bbe4cfcf35f25d536a2`，其安装与命名逻辑已晚于此前冻结的 `c9fabd1ef53e1a311dab4518a70693494631368b`。引用参考实现必须固定具体提交及文件散列，不能跟随 HEAD 漂移。
- 当前参考配置的驱动行为已在 2026-10-20 做过源码与构建对照，但真实切回故障曾在实际运行 16 kHz 时复现。把本机设备实际率调至 48 kHz 并清理遗留格式后，短时切回复测正常；完整长时、整机重启和 Intel 真机验收仍未完成。不能把采样率视为已经严格证明的唯一根因。
- `scripts/build-experiment-package.sh` 从历史实施记录读取参考补丁散列；`scripts/build-source-archive.sh` 将整个实施记录目录打入源码归档。整理文档时必须同时移除这种构建依赖，并更新归档内容。
- TapSay 产品身份、安装/卸载事务、许可材料已有实现。直接复制 MiRemoteV 身份或无线麦安装脚本会与独立产品边界冲突。

## 修正后的共同方向

1. 从固定版本的 BlackHole 源码、无线麦 USB 补丁和构建参数开始，在隔离工作区重建原样参考驱动，验证其来源、属性和实际音频链路。参考项目后续更新需先单独核对，不能直接混入基线。
2. 在参考基线可复现后，只做 TapSay 独立产品必需的身份替换、许可标注及独立安装包适配。旧 TapSay 驱动 C 文件、双 profile 分支和旧安装事务代码仅作为迁移兼容合同的检查资料，不作为新实现的复制来源。
3. 遥控器源音频保持 16 kHz；驱动起始默认率按参考为 48 kHz，实际设备及输出节点格式在每轮实测中读回确认。参考主程序的音频源以 16 kHz 单声道连接混音节点，没有找到在该路径强制写 48 kHz 输出节点的代码。若 TapSay 主程序与参考链路不同，记录差异并在实测证据支持下另列跨仓库改动。
4. 先完成原样参考链路、身份适配及真实验收，再考虑减少采样率、移除隐藏设备、缩小构建能力、清理额外属性或改恢复策略。此前所有优化均不得进入首个候选版本。
5. 在 `feat/61021` 新分支实现，只生成 `arm64` 正式候选资产。新实现通过后替换项目当前代码和文档，清理过期文件；Git 历史保留。可重建缓存、真实故障证据及安装恢复材料分开处理。系统已安装驱动和 macOS 音频设置不因仓库清理自动改变。
