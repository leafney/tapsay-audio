# 发布签名自动切换讨论

## 原始需求

暂时无法及时提供苹果开发者签名认证信息。推送 Tag 时仍需发布安装包，未认证包名称增加 `Unverified`；后续补齐 Secrets 后，无需修改流程即可发布认证包，名称自动去掉标识。

## 问答与补充

1. **部分 Secrets 已填写时如何处理？** 用户确认：Tag 发布仅允许全部为空或全部填写；部分填写时报错终止。
2. **手动触发如何处理？** 用户确认：只生成未认证的 Actions Artifact，供调试验证，不发布 Release。
3. **是否保留第三方分发审查门槛？** 讨论中说明现有门槛读取人工维护的状态，不自动判断许可。用户确认已完成审查，并要求更改为允许发布；该状态已在提交 `6031266` 中更新。未提出移除门槛。
4. **已发布未认证包后，如何发布认证包？** 用户确认使用新版本 Tag，保留不覆盖同名 Release 的规则。

## 共同理解

- 严格版本 Tag 触发双架构 Pre-release；两架构使用同一签名模式。
- 全部 Secrets 为空时发布标有 `Unverified` 的未认证 DMG；全部填写时执行 Developer ID 签名、公证和验证。
- 凭据部分填写或认证过程失败时停止发布，不自动降级。
- 手动构建继续只生成未认证调试 Artifact。
- 保留第三方分发审查、资产完整性检查和同名 Release 保护。
