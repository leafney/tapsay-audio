# Release 内容与状态调整讨论

## 原始需求

Release 说明只列出两次 Tag 之间的提交信息，不显示分支、合并提交或作者；不再上传项目生成的源码压缩包，因为 GitHub Release 已提供源码下载。后续 Tag 应创建正式 Release。

## 问答

1. **首个 Tag 没有上一个 Tag 时列出什么？** 用户确认列出截至该 Tag 的所有普通提交信息。
2. **存在其他分支的 Tag 时如何选择上一个 Tag？** 用户确认只考虑当前 Tag 历史中可到达的最近版本 Tag，避免使用未合并分支的 Tag。
3. **现有 `v0.1.0` Pre-release 是否改为正式版本？** 用户确认只处理后续版本，保留已有 Release 不变。

## 共同理解

- 后续发布说明保留签名和公证状态提示，再列出提交信息；排除合并提交和自动生成的 PR、分支、贡献者信息。
- 发布资产为两个架构 DMG 和它们的 `SHA256SUMS.txt`。源码使用 GitHub 提供的源码快照。
- 后续发布为正式 Release；已发布版本不修改。
