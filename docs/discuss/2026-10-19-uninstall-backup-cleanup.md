# 卸载后的历史安装备份清理

日期：2026-10-19
状态：需求已确认，补充 PRD 待批准；未授权直接删除系统备份。

## 原始请求

用户确认修复版卸载正常执行，截图显示“卸载完成”，但提示恢复备份仍保留于本项目 transactions 目录。用户认为这些文件在卸载后价值有限，询问是否也应提供移除操作，避免系统残留。

## 当前核实结果

- 用户提供的成功窗口显示：驱动文件、安装状态、收据已清理，系统中已无 TapSay Audio 设备。
- 本次只读检查确认系统 HAL 中的 TapSayAudio.driver 已不存在，指定安装收据也已不存在。
- 历史事务目录仍在，当前合计约 84 KB；它包含之前覆盖安装的恢复材料，不是正在使用的驱动。
- 现有实现明确保留 backup.driver，来自既有 PRD 对失败恢复来源的保护。用户反馈不是卸载失败，而是希望减少残留；“可选择清理”是代理最初建议，未获用户批准。
- 主程序由另一会话开发，本需求只属于 tapsay-audio 仓库。

## 首轮建议，尚未批准，现由后续简化方向替代

1. 卸载确认页增加“同时删除历史安装备份”，默认不勾选，明确删除后无法通过这些备份恢复旧版本。
2. 仅在驱动、状态和收据清理完成且目标 UID 已确认消失后，执行用户选择的备份清理。
3. 卸载失败、设备仍待重启或设备状态无法确认时，不删除恢复材料，提示本次清理未执行。
4. 用户已经卸载驱动时，也可重新打开工具，选择清理经验证属于本项目的历史安装备份，无需重新安装声卡。
5. 清理范围限本项目已核实的历史事务材料，不删除主程序、其他驱动、用户配置或身份不明的内容；清理失败单独报告，不把正常卸载改报为失败。

## 澄清问答

问题 1：是否同意在卸载前提供“同时删除历史安装备份”选项、默认不勾选，并允许已卸载用户再次打开工具清理？

推荐答案：同意。清理入口由用户主动选择，正常卸载成功后可以清干净，失败时保留恢复来源。

用户回答：提出另一种方向——安装时不备份，从源头避免卸载备份清理；安装成功使用新版，失败时可下载历史版本重新安装。用户认为普通用户通常不关心备份，收益有限。没有批准首轮可选清理方案。

问题 2：是否接受“取消长期历史备份，仅在覆盖安装事务中临时保留旧驱动；成功后自动清理，失败先自动恢复”的简化方案？

推荐答案：接受。用户不需要管理备份，也不增加卸载复选框；保留覆盖安装失败时自动恢复旧版的能力。

用户回答：“确认”。同意不保留长期历史备份，仅保留安装期间的临时回滚；正常成功后清理，不增加卸载清理复选框。

## 最终共同理解

- 用户目标是正常安装和卸载后没有长期历史备份，同时保留安装事务的临时恢复保护。
- 不再生成长期保留的 transactions/.../backup.driver，也不提供日常历史备份管理或用户恢复入口。
- 代码已存在事务内临时保留旧驱动的 previous 路径，正常失败回滚也实际使用该路径；保留此机制，去掉额外长期复制。具体事务恢复和异常退出处理在补充 PRD 明确，不能只删一行复制代码。
- 成功完成约定的安装检查后清理临时旧版；安装失败先恢复旧版，恢复成功后清理临时事务文件。仅失败且恢复也失败时保留必要恢复材料，并说明原因。
- 取消首轮建议的卸载清理复选框。新版卸载对经核实的正常历史残留自动清理；无法确认身份、事务进行中或待恢复的材料不得盲删，具体保护和结果反馈纳入后续规格。
- 这会调整已批准 PRD 的历史备份保留合同；产品方向已获确认，补充 PRD 的实现细节仍待批准。用户尚未授权本轮直接删除现有系统备份。
